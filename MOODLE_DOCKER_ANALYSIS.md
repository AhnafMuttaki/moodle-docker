# Moodle Dockerization Analysis Report

## Overview
This project provides a Docker-based environment for running two different versions of Moodle (4.0.5 and 5.0) in parallel. Each Moodle version has its own dedicated web application container and database container, allowing for isolated and simultaneous operation. This setup is ideal for plugin development and testing across multiple Moodle versions.

## Directory Structure
- `moodle-405/` and `moodle-500/`: Source code for Moodle 4.0.5 and 5.0, respectively.
- `moodledata-405/` and `moodledata-500/`: Data directories for each Moodle instance, mapped as volumes in Docker.
- `db-405/` and `db-500/`: Database directories for each Moodle version, each with its own `data` and `sql` subfolders.
- `docker/`: Contains shared configuration files for Apache, PHP, and Supervisor.
- `Dockerfile-405` and `Dockerfile-500`: Dockerfiles for building the web containers for Moodle 4.0.5 and 5.0, respectively.
- `docker-compose.yml`: Defines four services—two for Moodle web apps and two for their respective MySQL databases. Each service uses its own build context, environment variables, and volume mappings.
- `.env` and `example.env`: Environment variable files, with separate variables for each Moodle version (ports, DB passwords, etc).

## Dockerization Approach
- **Web Containers**: Each Moodle version is built from its own Dockerfile, which installs required PHP extensions, configures Apache, and sets up the Moodle source and data directories. Shared configuration files are copied from the `docker/` directory.
- **Database Containers**: Each Moodle version has a dedicated MySQL 8.4 container, with its own data and initialization SQL directories. Environment variables for root passwords and ports are separated for each version.
- **Volumes**: Source code and data directories are mounted as volumes to ensure persistence and easy development.
- **Networking**: Each web container is linked to its respective database container. Ports for web and database services are configurable via the `.env` file.

## Usage
- To build and run both Moodle versions in parallel, use `docker-compose up --build`.
- Access each Moodle instance via its configured port (e.g., http://localhost:8081 for 4.0.5, http://localhost:8082 for 5.0).

## Benefits
- Enables parallel development and testing of plugins or features across multiple Moodle versions.
- Isolated environments prevent conflicts between versions.
- Easy to extend for additional Moodle versions if needed.
